# ArchDisc / Archie / Forge Execution Pack
## Local-native CAD + CAE + CAM engineering system

This pack converts the uploaded video evidence, the uploaded Claude Code operating manual, and current public technical research into an executable engineering program for ArchDisc.

The central architectural decision is:

> **Archie is the engineering compiler front-end. Forge is the deterministic engineering runtime.**

Archie must not "draw a mesh that looks right" and call the task complete. It must convert intent, drawings, imported CAD, reference images, requirements, and engineering context into a typed, versioned engineering intermediate representation. Forge then executes that representation against a local C++ geometry/simulation/manufacturing stack, validates every mutation, commits only valid state, and produces editable engineering artifacts.

## Non-negotiable product doctrine

1. Fully local inference and execution by default. Internet search is an explicit tool, not a compute dependency.
2. Forge product code is C++-first and contains no JavaScript application dependency.
3. Geometry truth is B-Rep/parametric, not a rendered mesh.
4. Every generated object must remain editable through a persistent semantic feature/dependency graph.
5. Every engineering mutation is transactional: plan, dry-run, validate, commit or rollback.
6. Existing CAD editing is first-class and is benchmarked separately from generation.
7. Assemblies, kinematics, drawings, CAE, CAM, DFM, reports, and exports are views/products of one authoritative engineering graph.
8. "Real time" is tiered. Interactive reduced-order or incremental previews may be real-time; high-fidelity CFD/FEA is not falsely branded as instantaneous.
9. The AI never drives CAD by screen coordinates as its primary interface. It calls typed deterministic operations.
10. Resource safety is part of correctness. A result that causes the workstation, UI, GPU stack, or build environment to collapse is a failed result.

## Build ordering

Do not attempt all of CAD, CAE, CAM, multimodal training, and large assemblies simultaneously. The correct dependency chain is:

**Safety supervisor -> typed IR -> document/feature graph -> kernel transaction engine -> sketches -> core solid features -> persistent naming/recompute -> import/export -> semantic editing -> assemblies -> drawings/BOM -> DFM -> CAE preview -> higher-fidelity solvers -> CAM -> multimodal Archie training -> large-assembly optimization.**

Parallel work is allowed only where write sets and dependency boundaries are explicit.

## Meaning of "Astra-level"

Treat "GPT-6 Astra-level" as a **system-quality aspiration**, not as a claim that QLoRA can make a 20B local model equivalent to a frontier general-purpose model. The path to frontier-like engineering behavior is specialization:

**strong local reasoning model + exact typed tool interface + huge verified synthetic curriculum + deterministic kernel + engineering validators + recovery loop + memory/retrieval + execution-grounded reward.**

The moat is therefore not merely the model weights. It is the closed engineering execution loop and the proprietary corpus of verified plans, successful edits, failure recoveries, topology-preserving transformations, DFM decisions, simulation traces, and user-approved outcomes generated by Forge itself.
