# License, Dependency and Data Governance

## Why this is part of architecture

ArchDisc’s moat is intended to become a commercial product. A technically excellent model or solver can create a major business constraint if its dataset or code license is incompatible with the distribution model.

Maintain an SPDX-style registry for **every**:
- source dependency;
- executable sidecar;
- model;
- adapter;
- dataset;
- benchmark;
- generated derivative corpus.

No dependency moves from `research` to `shipping` without a recorded review.

## Current high-value items

| Item | Technical use | Current public licensing signal | Architecture treatment |
|---|---|---|---|
| gpt-oss-20b | Local reasoning model candidate | Apache 2.0, subject to usage policy | Strong candidate; pin model hash and policy version |
| llama.cpp | Local C/C++ inference runtime | Verify pinned upstream release license | Embed behind Forge inference interface |
| Open CASCADE Technology | B-Rep/modeling/data exchange | LGPL 2.1 with additional exception | Strong kernel foundation; comply with notices/terms |
| MFEM | Finite element discretization | BSD | Strong native C++ CAE candidate |
| PETSc | Numerical solvers | 2-clause BSD | Optional numerical backend |
| SU2 | CFD/multiphysics | LGPL 2.1 | Prefer separate solver adapter; review distribution/linking |
| OpenFOAM | CFD | GPLv3 | Do not casually link into proprietary core; optional external-process strategy only after review |
| SearXNG | Metasearch | AGPL-3.0-or-later | Local sidecar over HTTP; comply with AGPL for distributed service |
| libigl core | Geometry processing | Primarily MPL2, subdirectories vary | Allowlisted modules only; avoid copyleft submodules unless reviewed |
| CGAL | Geometry algorithms | mixture of LGPL/GPL or commercial | Package-by-package review; avoid accidental GPL contamination |
| Gmsh | Meshing | GPL with stated exception/other licensing considerations | Do not embed until exact distribution architecture is approved |
| fTetWild | tetra meshing | MPL2 project, dependency caveats | Review dependency closure before shipping |

This is engineering guidance, not legal advice.

## Dataset policy

### RED — non-commercial/research-only by default

**MM-CAD:A / MMCAD**
- aggregation contribution: CC BY-NC 4.0;
- underlying models have per-source terms;
- ShapeNet-related restrictions are explicitly discussed by the dataset maintainers.

**Fusion 360 Gallery Dataset**
- public license restricts dataset use to non-commercial research.

These are excellent research/evaluation inputs but must not be assumed safe for a commercial Archie checkpoint.

### AMBER — provenance/license must be individually reviewed

- ABC-derived corpora;
- DeepCAD;
- SketchGraphs;
- Text2CAD;
- CAD-Coder;
- CAD-Recode;
- MFCAD;
- ShapeNet;
- Thingi10K;
- PartNet/PartNet-Mobility;
- any scraped CAD repository;
- any vendor/community CAD model.

Repo code license does not automatically license training data.

### GREENEST PATH — ArchDisc-owned synthetic corpus

The long-term training corpus should be generated by Forge itself from:
- original procedural grammars;
- owned/commissioned seed designs;
- permissively licensed primitives;
- public-domain standards/data where actually public domain;
- user-contributed data only under explicit training terms.

Every synthetic shard stores provenance:
- generator version;
- seed;
- source rights class;
- IR;
- validation result;
- derivatives;
- adapter/checkpoint IDs trained on it.

## Dataset ingestion gate

Before ingesting a corpus:
1. identify owner/source;
2. capture exact license text/version/date;
3. distinguish code license from data license;
4. check commercial-use permission;
5. check derivative/redistribution constraints;
6. check attribution;
7. check user-data/privacy restrictions;
8. record allowed purposes: `research`, `evaluation`, `training-internal`, `commercial-training`, `redistributable`;
9. hash files;
10. only then add to catalog.

## Model lineage

Every Archie checkpoint has a machine-readable model card:
- base model/hash/license;
- tokenizer;
- adapters;
- dataset shard IDs;
- training code version;
- hyperparameters;
- evaluation suite;
- safety tests;
- known limitations.

If a dataset later becomes legally unusable, lineage must allow identifying all affected checkpoints.

## Search-derived data

SearXNG results are retrieval context, not automatically training data.

Do not continuously scrape and train on arbitrary web content because it was retrievable. Retrieval and training rights are different concerns.

## User project data

Default:
- private to local project;
- not included in global Archie training corpus.

If future product UX offers local personalization, keep that adapter/data local by default and isolate it from the distributable base model unless explicit rights exist.
