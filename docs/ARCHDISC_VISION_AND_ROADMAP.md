## 0. Read this first — the honest framing

ArchDisc's ambition is an **AI-native engineering platform**: a user downloads
it, plugs in any LLM/SLM, types a prompt, and the platform autonomously plans,
clarifies, constructs, tests, analyses, renders, assembles, and publishes a
complete engineering project — at a granularity beyond expert engineers.

The honest current state, stated plainly so no one is misled:

- ArchDisc is **not** at parity with ACIS / Parasolid / Siemens NX / SolidWorks /
  Autodesk. It is early-stage.
- Its working modeling kernel is **`manifold-3d`** — a robust *mesh / triangle
  boolean* kernel. It is **not an exact boundary-representation (B-rep) kernel**.
  It cannot do exact NURBS surfaces, exact trimmed topology, exact fillets,
  tolerant modeling, or most of the capability list in §3.
- The **AI integration is genuinely strong** — a BYO-LLM provider layer (cloud +
  local SLM) works, and an autonomous LLM-driven CAD pipeline has been built and
  proven end-to-end (see §6).
- A real autonomous run was attempted (build an Omega Seamaster). It produced 23
  component STEP files **fully autonomously**, but **0 passed verification** —
  the geometry kernel cannot produce convincing watch parts. That is the honest
  result and it correctly diagnoses the core gap (§7).

**The single biggest blocker between today and the vision is the geometry
kernel.** Everything else (AI orchestration, UI, simulation) is meaningful work,
but without an exact B-rep kernel the platform cannot construct real engineering
geometry. Plan accordingly — do not let AI-orchestration progress disguise the
kernel gap.

## 1. The Vision

### 1.1 Plug-and-play AI onboarding

- The user **downloads the software** (desktop app — ArchDisc is Electron).
- The user **enters their LLM/SLM configuration** into the software (API
  endpoint, key, model — any provider, cloud or local).
- The software **sends multiple test signals** to fully confirm the model
  connection works, and the status **turns green** only when confirmed.
- BYO model: any LLM or SLM, plug and play. (Foundation for this exists — §6.)

### 1.2 Prompt → end-to-end planning → MCQ clarification

- The user **enters a prompt** describing the project to build.
- The platform performs **full end-to-end planning** — this may take anywhere
  from **minutes to hours**.
- The platform presents the user with **anywhere from single-digit to
  triple-digit multiple-choice questions (MCQs)** to answer — exhaustively
  resolving every ambiguity, misunderstanding, and potential mistake **before**
  any construction begins.

### 1.3 Autonomous swarm construction

- After all MCQs are answered, the AI **begins implementing the plans**.
- It **creates, constructs, tests, analyses, and renders** the project **one
  component at a time**, with **swarm agents working in parallel** across
  components.
- The workflow follows **the same manner a manual expert user would** — from the
  ground up — but with **microscopic refinement not achievable by a human**.
- From **detailed sketches → precise modelling → engineering excellence**, built
  with **creativity and accuracy**.
- Each component is fully completed (constructed, tested, analysed, rendered)
  and **saved with an id** before moving to the next.

### 1.4 Final assembly

- When **all components are fully achieved**, the platform performs the **final
  assembly** of all components into the complete project.

### 1.5 Publishing (the last step — many steps precede it)

- A **full suite for all types of publishing** of the finished project.

## 3. Geometry kernel — the required capability set (ACIS / Parasolid parity)

This is the capability list the platform must reach. Today ArchDisc has **almost
none of it** (it has mesh booleans only — see §6). This list IS the kernel
roadmap.

### 3.1 Blending & Filleting
- **Variable Radius Blending** — smoothly changing radii across non-uniform surfaces.
- **Cliff-Edge Blending** — blends that completely consume or run off adjacent faces.
- **Corner Mitering** — resolving the intersection of three or more complex blends at one vertex.
- **Curvature-Continuous (G2) Blending** — matching surface *curvature rates*, not just tangency, across splines.

### 3.2 Local Operations
- **Complex Face Offsetting** — offsetting intricate high-curvature surfaces without self-intersection.
- **Hollowing & Shelling** — thin-walled solids from models with sharp, tight interior corners.
- **Drafting Spline Faces** — taper angles applied to complex non-planar surfaces.
- **Thickening Sheets** — converting a complex open surface into a valid watertight solid.

### 3.3 Advanced Surfacing
- **N-Sided Patching** — filling a gap bounded by an arbitrary non-four-sided loop of curves.
- **Sweeping Along Tortuous Paths** — preventing self-intersection when a profile sweeps tight 3-D curves.
- **Lofting with Tangency Constraints** — smooth surfaces through multi-profile guides with boundary conditions.

### 3.4 Boolean & Topology Alterations
- **Non-Manifold Booleans** — intersections that result in zero-thickness walls or shared edges.
- **Coplanar / Coincident Face Booleans** — uniting/subtracting bodies with perfectly overlapping faces.
- **High-Density Lattice Intersections** — intersecting thousands of microscopic beams in generative-design models.
- **Local Face Replacement** — swapping underlying geometry while dynamically rebuilding surrounding topology.

### 3.5 Healing & Conversion
- **Tolerant Modeling / Stitching** — sewing imported surfaces with gaps larger than standard tolerances.
- **Geometry Simplification** — removing tiny features, sliver faces, small edges automatically.
- **Convergent Modeling** — performing classic B-rep operations directly on facet/mesh data.

### 3.6 Evaluation & Checking
- **Clash & Interference Detection** — exact intersection zones within massive assemblies of complex parts.
- **Self-Intersection Detection** — scanning highly warped spline surfaces for crossings.

> **Honest engineering note.** Items in §3.1–§3.5 fundamentally require an
> **exact B-rep / NURBS kernel**. `manifold-3d` (mesh) cannot do them. Reaching
> this list means **building or integrating an exact kernel** — a multi-year,
> specialist effort, or licensing one. This is the platform's foundational
> decision. Convergent modeling (§3.5) and clash/self-intersection (§3.6) are
> the items most reachable on a mesh kernel.

Comprehensive Exhaustive Reference of Parasolid and ACIS Kernels: Functions, Features, and Mathematical ImplementationsIntroduction to Geometric Modeling and Boundary RepresentationThe computational representation of three-dimensional physical objects within computer-aided design (CAD) systems relies fundamentally on the underlying geometric modeling kernels. These kernels serve as the absolute mathematical engines that evaluate, define, and manipulate geometric and topological data structures. Two dominant architectural paradigms have historically driven this industry: the Parasolid kernel, currently maintained by Siemens Digital Industries Software, and the ACIS kernel, maintained by Spatial Corporation (Dassault Systèmes). Both systems utilize Boundary Representation (B-Rep) as their primary paradigm for defining solid models, establishing a rigorous hierarchy of topological entities that enclose a defined volume in Cartesian space.Within the mathematical framework of Boundary Representation, a solid model is defined by its enclosing boundaries, separating the interior domain (solid material) from the exterior domain (empty space). The fundamental theorem governing these topologies is the Euler-Poincaré characteristic, represented by the equation $V - E + F = 2(S - G)$, where $V$ denotes vertices, $E$ edges, $F$ faces, $S$ shells, and $G$ the genus (the number of holes through the solid). Both the Parasolid and ACIS kernels implement data structures that strictly maintain topological consistency by preserving this mathematical invariant during boolean operations, sweeping, lofting, and primitive construction. The implication of this mathematical absolute is that any function altering the topology—whether splitting a face or collapsing a vertex—must simultaneously trigger balancing operations across the surrounding B-Rep graph to prevent non-manifold corruption.While the underlying mathematical objectives of both kernels are identical—calculating the intersection of parametric surfaces, managing B-spline curves, and maintaining non-manifold and manifold topologies—their architectural implementations, memory management paradigms, and application programming interfaces (APIs) diverge significantly. The ACIS kernel is strictly object-oriented, utilizing C++ class hierarchies and functional macros to manage transactions. In contrast, the Parasolid kernel utilizes an ANSI C-callable interface characterized by a rigorous tag, token, and identifier system, operating on entity classes through generalized standard forms. The hierarchy cascades from volumetric space down to zero-dimensional points. The highest level of a model object is the BODY, which represents a completely independent spatial entity in the global coordinate system. A BODY is composed of one or more LUMP entities. A LUMP is mathematically defined as a one-dimensional, two-dimensional, or three-dimensional set of points in continuous space that is entirely disjoint from all other lumps within the same body.A LUMP is physically bounded by SHELL entities. A SHELL is a connected set of faces and wires that can bound the outside of a solid or define an internal void (a hollow volume). For internal computational efficiency when parsing complex volumes, ACIS implements a SUBSHELL class to further decompose shells into manageable memory blocks. The exterior boundary of a SHELL is composed of FACE entities. A FACE is a connected portion of a geometric surface bounded by a set of LOOP entities. A FACE serves as the primary building block for shells, and its spatial geometry is defined by an underlying bounded or unbounded parametric 3D surface, which may be an infinite plane, an ellipsoid, or a non-uniform rational B-spline (NURBS) surface.The boundary of a FACE is represented by LOOP entities, which consist of a connected series of COEDGE entities. The COEDGE is a fundamental element of the half-edge data structure utilized by ACIS; it represents the directed use of an EDGE by a FACE. Because adjacent faces share a single physical edge, the COEDGE provides the necessary topological directionality to traverse the perimeter of a face in a consistent mathematical orientation (typically counter-clockwise relative to the outward-pointing surface normal). A WIRE is similarly defined as a connected series of coedges that are not attached to a face, representing standalone wireframe models.The fundamental bounding curve mapping the intersection between spaces is the EDGE, which is a parametric or analytic curve strictly bounded by VERTEX entities. Finally, the VERTEX represents a zero-dimensional spatial location in object-space (a defined Cartesian point). A vertex can be referenced by multiple edges simultaneously, and it maintains pointers to those attached edges to facilitate rapid topological graph traversal during boolean evaluations.Parasolid Topology and Standard FormsThe Parasolid kernel operates on an explicitly defined class hierarchy utilizing tokens, tags, and standard forms rather than C++ objects. Every object within the Parasolid environment is assigned a class, denoted by constant tokens defined in the parasolid_kernel.h header file. Tokens take the format PK_<CLASS>_<text> or PK_<text>. The primary top-level classes are PARTITION, SESSION, PMARK, ERROR, MARK, MEMORY, DELTA, and ENTITY.Within the ENTITY class, Parasolid branches into distinct functional subclasses: ATTRIB (attributes), ATTDEF (attribute definitions), TOPOL (topology), GROUP, TRANSF (transformations), and GEOM (geometry). The topological hierarchy (TOPOL) mirrors the B-rep structure of ACIS but utilizes unique nomenclature and structural relationships. The primary topological classes in descending order of dimension are PART, REGION, SHELL, FACE, LOOP, EDGE, FIN, and VERTEX.A solid model in Parasolid is categorized as a BODY, which contains topological subdivisions called regions. These regions are bounded by shells, which in turn are constructed from faces. The faces are bounded by loops. Parasolid utilizes the FIN entity as its directed topological construct, serving the exact same mathematical purpose as the COEDGE in ACIS. A fin represents the directed traversal of an edge by a specific face loop, managing adjacent face directionality.Geometric entities (GEOM) in Parasolid are segregated from topology, defining infinite mathematical spaces rather than bounded limits. Geometry includes spatial constructs such as SURF (surfaces), CURVE, and POINT.
