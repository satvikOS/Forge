## Auto-update: what deleting these manifests does

`latest.yml` / `latest-mac.yml` / `latest-linux.yml` are the electron-updater
channel manifests. A running installed copy of the app polls them, compares
versions, and downloads the installer named inside.

**Deleting them strands any installed client on the version it already has.**
The app keeps working, but it will never update again, and `checkForUpdates()`
fails. `electron/main.js` swallows that error (`autoUpdater.on('error', ...)`
only logs), so a stranded client shows no user-facing failure — it silently
stops receiving updates. Reporting this rather than deciding it silently was a
condition of this cutover.

### Measured evidence on how many clients that is

| Signal | Measured |
|---|---|
| Downloads of `latest*.yml`, summed over all 871 releases | 104 per platform (312 total) |
| Maximum downloads of any single `latest*.yml` file | **1** |
| Downloads of every asset of `v1.0.1145` (newest, published 2026-08-28) | **0** |
| Total downloads, all 12172 assets, all time | 2450 |

An installed client base auto-updating would concentrate polls on the newest
release's manifest, because that is the file electron-updater resolves. The
newest release has **zero** downloads on all 14 of its assets. Downloads are
instead spread thin and uniformly (0 or 1 per manifest, max 4 per installer)
across three months — the signature of crawlers and CI mirrors, not users.

Two further facts bound the risk:

- Builds were **unsigned**. `build-app.yml` documents that macOS Gatekeeper
  blocks first launch and "auto-update is unreliable without notarization", and
  Windows shows SmartScreen warnings. Auto-update was already not dependable.
- No first-party code outside the retired app consumes this feed. The only
  consumers in the repo are `electron/main.js` and `electron-builder.yml`,
  both part of the product being retired.

The honest statement is therefore: **the evidence indicates no real installed
user base, but it cannot prove zero.** Anyone who did install the app keeps a
working copy pinned at its current version, with no upgrade path.
